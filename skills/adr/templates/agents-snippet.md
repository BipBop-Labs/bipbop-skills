## Architecture decisions, policies and procedures

Decisions that constrain this codebase live in `docs/adr/`. Before you change a
dependency, a module or service boundary, a data model, a public interface, or
code marked `@decision ADR-NNNN`, read `docs/adr/README.md` and the ADRs
whose `paths` match the files that you change. Accepted ADRs are binding. To change
one, get confirmation and rewrite the affected records in place. Consolidate
overlap, and remove obsolete records and references. Never silently undo a
constraint. Keep the collection concise. Git keeps the history. Do not add
replacement chains or `History` sections.
`docs/adr/known-debt.md` lists things that look deliberate but are not. You
can fix those.

Rules to obey live in `docs/policies/`. Steps for a task live in
`docs/procedures/`. Read the index of each folder. Open only the docs whose
`paths` match your work. One rule, one doc: in this file, keep one line per
rule that names its source. Do not restate the rule.
